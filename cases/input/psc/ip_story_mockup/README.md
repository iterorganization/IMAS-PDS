# ip_story_mockup: scenario story 105073, PSC events, segment changes and MCLS mode changes in one closed-loop pulse

One closed-loop `evolutive_controller` pulse of ITER 105073 (window 115.817598 s to 138.0 s) in which the PSC pulse
schedule exercises, at physical times, several events, segment changes and magnetic-control-mode changes: end of flux
on the CS1 headroom, a soft ramp-down overlay, an automatic MCLS mode change when |Ip| crosses 13.5 MA (gap control
off), a watchdog escalation to a hard termination segment that forces the MCLS termination mode, and STOP; a Z
excursion rule on the current centre is armed (z_hold, escalating to ip_termination) and ip_too_high is armed but
silent. Every threshold, rate, window and watchdog time is a study value, not an ITER operational value. Maturity:
PDS demonstration.

## Scenario (segments of the PSC schedule)

As defined by the user (`scenario.txt`, copied unchanged; the names in `psc_config/` are given in the last column):

| id | name | kind | Refgen outputs | name in `psc_config/` |
|---|---|---|---|---|
| 0 | ftop_rdwn | Nominal segment | Designer Ip ref ~15MA, then 0.2MA/s ramp-down | flattop_rampdown |
| 99 | STOP | Nominal end segment | Freezes last values | STOP |
| 21 | eof_rdwn | Soft overlay on Ipl_ref, triggered by end_of_flux while in 0 | Ip rampdown at 0.2MA/s for 15s, then 42 | eof_rampdown |
| 22 | z_hold | Soft overlay on Ipl_ref, triggered by z_excursion while in 0 | Hold Ip ref until flag drops, else 41 after 2s | z_hold |
| 41 | ip_term | Hard exception, triggered by ip_too_high or z_hold watchdog | Ip rampdown from 8MA at 2MA/s, MCM3, then 99 | ip_termination |
| 42 | eof_term | Hard exception, reached by watchdog 21 | Ip rampdown from 12MA at 0.4MA/s, MCM3, then 99 | eof_termination |

Exact values (from `ip_story_mockup.yaml`): end_of_flux when cs_margin < 4500 A per turn (release 4700 A, latched);
z_excursion when |z_meas - 0.5812 m| > 0.08 m (release 0.04 m), z_meas = NICE `global_quantities.current_centre.z`;
ip_too_high when |Ip| > 15.5 MA; 21: Ipl_ref 15.07 -> 11.92 MA over 15 s, watchdog 15 s -> 42; 22: hold, watchdog 2 s
-> 41; 41: 8.0 -> 0 MA over 4 s, hold 0.5 s, watchdog 4.5 s -> STOP; 42: 11.92 -> 0 MA over 29.8 s, hold 0.5 s,
watchdog 30.3 s -> STOP; segment 0 watchdog 60.6 s -> STOP.

## MCLS modes (`mcls_table.yaml`)

| MCM | Name | VS | Ip | ShapeIp | SCIpScaling | Ip window (A, PCS frame) | NextEnabledModes | reached by |
|---|---|---|---|---|---|---|---|---|
| 1 | flattop_gaps | 3 (VS1+VS3) | 1 (KCURR) | 4 (gaps) | 1 | [13.5e6, 20e6] | [1 2] | StartingMode |
| 2 | rampdown_position | 3 | 1 | 0 (off) | 1 | [0, 13.5e6] | [2] | automatic, \|Ip\| < 13.5 MA |
| 3 | termination | 3 | 1 | 0 | 2 | [0, 20e6] | [3] | PSC force field 3 in segments 41 and 42 |

The force field is the PSC output `force_control_mode` added by `preprocessing/psps/make_mcls_psc_config.py`
(3 in segments 41 and 42, 0 in segment 0 and in the overlays, held in STOP). Gap shape control is dispatched by the
MCLS (`mcls_shape_enable: 1`). The transition rule of the block is summarised in the header of `mcls_table.yaml`.

| File | Content |

How the PSC files were made: converter with `--cut-at 115.817598 --psc-config --refgen --ids` on the
designer file, then `python preprocessing/psps/make_mcls_psc_config.py <converter output>/psc_config_<design name>
<dir> --force eof_termination=3 --force ip_termination=3` (re-run on 2026-11-21 with the committed script: identical
files except three label words in XML comments and one description attribute).

The PSC files were generated by the converter of 2026-11-16 and are kept as run. Regenerating them with the
committed converter changes the behaviour: in BTree.xml the sudden `ip_too_high` exception fires only from the
nominal segment and the `PathSegStop` action gets `entryRule="Step"`; in PS.xml the STOP segment carries an explicit
Ipl_ref = 0 trajectory (the v1 files freeze the last values in STOP, as in the reference run).

### PSPS dataset (JSON)

`ip_story_mockup_psps_dto.json` and `ip_story_mockup_psps_dto_extended.json` hold the design in the psps-dto/v1.0 JSON
format of the ITER PSPS editor (DTO = Data Transfer Object): the strict file has only what that format holds, the
extended file is the strict content plus the PDS extensions. Generated on 2026-11-21 from `ip_story_mockup.yaml` with
`--cut-at 115.817598`, exported with the converter's PSPS DTO exporter (not yet committed). Both files pass the CODAC
parser `parse-psps-file` (psps-dto 1.4.0); the strict file is identical (839 values) to the export of 2026-11-16 made
for the reference run.

## How to run

The controller model with the MCLS (`controllers/CCS/pcssp_controller_and_ps_mcls.slx`) must exist (build:
`controllers/CCS/mcls/model_build/build_mcls_controller.sh`). From the repository root:

```bash
mkdir -p cases/runs/psc_logs
DRY_RUN=1 VARIANT=ip_story_mockup bash workflows/evolutive_controller/run_psc_cases.sh
sbatch --time=01:30:00 --chdir=$PWD --export=ALL,PDS_REPO=$PWD,VARIANT=ip_story_mockup,SHORT_WINDOW=1 workflows/evolutive_controller/run_psc_cases.sh
sbatch --time=03:30:00 --chdir=$PWD --export=ALL,PDS_REPO=$PWD,VARIANT=ip_story_mockup workflows/evolutive_controller/run_psc_cases.sh
```

The launcher builds `cases/evolutive_controller_105073_ip_story_mockup` (with `SHORT_WINDOW=1`:
`cases/evolutive_controller_105073_ip_story_mockup_smoke`, window 115.817598 -> 116.02 s, a smoke check of the
initialisation and of the exchange with NICE), expands the override, switches the controller to the standard program
`magnetic_controller_psc` and runs the case (about 2.5 h of wall time for the 22.2 s of plasma at ~6.5 min per plasma
second, plus ~10 min of MATLAB/PSC init; `RUN_TIMEOUT` default 3 h). Outputs: the run directory
`cases/runs/evolutive_controller_105073_ip_story_mockup_<stamp>/` with `mcls_log.csv`, `mcls_diary.txt` and
`simulink_log.csv`.

## End of the run (138.0 s)

`torax.t_final` and `nice_evo_rd.t_end` are 138.0 s, shortly after the PSC STOP of the reference run (137.88 s, below).
The plasma of that run was lost by an upward VDE at 131.45 s and the data are not physically valid from 131.46 s: **the
results after 131.46 s are not physical**; the remaining 6.5 s only show the PSC and MCLS sequence (z_hold, hard segment
41, forced MCM3, STOP) acting on that non-physical state. The reference run went on to 176.5 s, 45 s of plasma time
spent on that state.

The run cannot stop by itself at the PSC STOP today, so the end is a fixed time:

- the controller (`controllers/CCS/muscle_controller_NICE_IMAS_iter_init.m:48` `reuse_instance`, `:344` `sim(in)`) runs
  the Simulink model once and stops it on `stop_signal` from `controllers/CCS/muscle_nice2control.m:36-62`, i.e. when
  NICE sends its last message (no `next_timestamp`) or closes its port;
- NICE evo_rd (`local_installs/nice` at `3fc04ac9`, `src/main_imas_evo_rd_muscle3.cc`) bounds itself only by its
  `t_end` setting (`:110`, `:185`) and, while `t_next <= t_end`, receives `pf_active_s`, `core_profiles_s` and
  `equilibrium_s` every exchange step (`:174-203`) through `receive_imas_data` (`src/nice_imas_muscle3.h:144-157`),
  which has no closed-port handling;
- an early end of the controller at the PSC STOP would therefore close the port NICE still receives on, so NICE would
  fail and the manager would shut the whole run down, recorders included; TORAX and the temporal coupler would also
  need a coordinated end. Analysis of 2026-11-16 in the PDS main repository,
  `docs/psps/work_notes/psc10_F_story_v2_2026-11-16.md` section 2.5 (line numbers re-verified on 2026-11-21).

## Reference run (v1, 2026-11-16, Slurm job 1319834)

Run directory (not in the repository; the case was then called `psc_mcls_story`):
`cases/runs/evolutive_controller_105073_psc_mcls_story_20261116_131529`. This run used the window end 176.5 s.
Notes in the PDS main repository: `docs/psps/work_notes/psc8_F_story_design_2026-11-16.md` (design) and
`docs/psps/work_notes/psc10_F_story_v2_2026-11-16.md` (section 1: results of this run).

- end_of_flux at 119.55 s -> soft overlay 21 (eof_rampdown);
- MCLS MCM1 -> MCM2 at 127.23 s (|Ip| < 13.5 MA; `mcls_log.csv`, gap control off from then on); a vertical
  oscillation that had started growing at about 123.5-124 s, still in MCM1, grew faster after the switch;
- plasma lost by an upward VDE at 131.45 s; the data are not physically valid from 131.46 s (|Zcc - Zref| > 0.5 m);
- z_hold 22 -> watchdog -> hard segment 41 (ip_termination) at 133.38 s; MCM3 forced at 133.79 s (the Linear entry

## Differences of the committed set-up from the reference run

- controller program `magnetic_controller_psc` with `mcls_enabled: 1` instead of the separate program and init copy
  (same model, same PSC handling, same VS gain update path; the model is fixed by `mcls_enabled`, the former setting
  `controller_model` is gone);
- MCLS table read from `mcls_table.yaml` with `mcls_load_table.m` instead of a `.mat` (same completion code; the
  settings report is now written at run time to `RUN_DIR/mcls_diary.txt`);
- run end 138.0 s instead of 176.5 s (`torax.t_final`, `nice_evo_rd.t_end`; section "End of the run");
- PSC files and table in this folder (PSC files byte-identical to those run); the designer YAML and the RefGen export
  renamed `ip_story_mockup.yaml` / `ip_story_mockup_refgen.xml` (content unchanged, names inside unchanged);
- launcher `workflows/evolutive_controller/run_psc_cases.sh` (`VARIANT=ip_story_mockup`): case and run directory names
  `..._ip_story_mockup` (the reference run: `..._psc_mcls_story`), logs in `cases/runs/psc_logs`, and the init-lock wait
  only accepts a run directory of the current submission (fix of 2026-11-16 evening; it changes when the lock is
  released, not the simulation);
- `controllers/CCS/mcls/third_party/MCLS.m`: one comment line reworded (the script embedded in the model is the one
  of 2026-11-16).
